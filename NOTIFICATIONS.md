# Gaps met by the startcloud-ui growth

- `src/lib/cookieSession.js` `savePreferences(patch)`: the identity contract's cookie provider table says "`PATCH /api/user/preferences`, then the cached profile's `preferences` updated", while its Principles say the page "keeps a display cache of the profile (`name`, `email`, `picture`, `roles`, `organizations`, never the address, the birthdate or the preferences)" and the `load()` row says it "caches the display fields"; the provider patches and updates nothing in the cache. Section: The cookie session provider. Needed: the `savePreferences` row amended to match the display-only cache, or the cache widened.
- `src/lib/runtime.js` `status.analytics`: the identity contract's status table (`analytics` row) says a `script_url` on a host outside the estate is not appended on the sign-in, onboarding, interstitial and error routes, but no contract gives the UI the estate's hosts to decide with; the shell appends the tag on every page. Section: The issuer's status payload. Needed: how the UI learns the estate's hosts, or the rule that the server omits `analytics` when the host is outside the estate.
- `src/hooks/useSession.jsx` and `login_method`: the growth guide's §3a step 1 row names `src/hooks/useSession.js` "for `login_method`", while the identity contract's sign-in table says "`login_method` in local storage read by the page; `login_mode` in the methods answer seeds it" and the session contract's Storage table lists it as the sign-in page's key; nothing was changed in `useSession` for it. Sections: UI-GROWTH-GUIDE §3a step 1, identity What this design changed for sign-in. Needed: the sentence giving `useSession` a job for the key, or the guide row corrected.
- `src/components/layout/Sidebar.jsx` tree entries: the navbar contract's Sidebar section says a group carries `sections | tree | views` with `views` as `[{ key, labelKey, useTree }]`, and the mockup's `useTree()` answers `{ nodes, menu }` with nodes `{ key, icon, label, to, children(), status }`, but no contract fixes the shape of a bare `tree` member (a hook like `useTree`, or a static `{ nodes }`) nor the node and menu shapes; the shell reads `tree` as a hook answering the mockup's `{ nodes, menu }` shape. Section: navbar Sidebar, Export. Needed: the `tree` member's shape and the node shape written into the Export bullet.
- `src/features/identity/sidebar.js` Configuration row: the identity contract's admin routes table and Sidebar export make `/admin/config` a row `{ key, icon, labelKey, to }` like every other, while What the admin pages draw says the row is "reached from the sidebar row as a top-level navigation into the old chrome" until the shared editor lands; the row shape has no member for a top-level navigation, so the row is an in-router `to`. Section: identity group 5, Configuration. Needed: either a row member for a top-level navigation or the sentence dropped once the shared editor is the target.
