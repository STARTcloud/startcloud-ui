hyperweaver's order. The toolbar row sits above the pane and the pane opens below it at the bottom of the screen, as hyperweaver-ui's Footer.jsx draws it; the center of the row carries the grip bars alone, hyperweaver's sixty-pixel grip spot, the mark moved to the far left. Without a pane token the center is today's Powered by text and mark and the left carries no mark.
Inside the row the grip alone drags. While the pane is open the grip in the middle of the row is the handle, and nothing else in the row, so a press on a button or a link is never a drag: press the grip, hold and drag up to grow the pane, down to shrink it, under 100px it closes, as hyperweaver's does; it grows to ninety percent of the window, hyperweaver's own limit, the page region giving way; opened from closed it starts at 130px, hyperweaver's number; the height persists per origin. Closed, the grip is still. No resizable library, pointer events on the grip setting the pane's height.
The top edge and the corner. The row's top bound is a handle too, "the same resize thing" the sidebar has left to right, turned on its side: a strip over the row's top border, above the row and never over a button, dragged up and down to set the pane's height; dragged up from a closed pane it opens the pane at the height it is dragged to, and released at 100px or under it closes. Beside a sidebar the corner where the sidebar's right edge meets this top edge is one handle for both, "a 2 axis resize to control both": one drag sets the sidebar's width and the pane's height, the pointer there the four-way arrows; the sidebar's page draws it.
Right cluster. The heart while health is listed, then the Shell toggle while the host lists host-terminal, the Tasks toggle while it lists tasks, Refresh, the priority filter and the Columns picker while the tasks pane shows, then the chevron that collapses or expands the pane. Refresh reads the tasks again, the "just in case" read a person asks for. A saved view whose token the host lacks falls to the one it has.
The row's height. 36px under a 1px top border, no vertical padding, because "there is this padding on top and below the buttons the entire footer could do without"; the sidebar's foot is the same 36px under the same border, so the two top borders are one line across the column. The tools fill the row's height, joined with no gap between them, and sit hard right, against the window's edge, hyperweaver's manner; a row without tools keeps the 20px gutter.
One Shell, whatever opens it. The footer offers a Shell while the host in focus lists one: "a shell via a pty, a shell via ssh, a shell via some other mechanism", the mechanism the backend's own. The pane is written against a terminal source, the route that starts the session, its WebSocket, its ticket and the route that stops it, never against one kind of shell; today's source is the host shell behind host-terminal, as hyperweaver's footer opens it, with Reconnect shell, Restart shell and Terminal preferences in the toggle's drop-up. Reconnect shell opens a new socket to the same session, the session left running; Restart shell stops the session and starts a new one; a closed socket is never opened again on a clock. A terminal per machine and "a tabbed shell per vm" are later work.
The pane's own menu. A right-click on the pane opens hyperweaver's menu at the pointer, titled by the view: Reconnect shell, Restart shell and Terminal preferences on the shell, Refresh on the tasks; Escape, a click away or a second right-click elsewhere closes it.
A task row opens its dialog. Details, progress, metadata, the output in terminal colors with Copy, the subtasks each opening its own dialog, and Cancel task behind a confirmation while the task is pending or running. On the all-hosts view a row opens nothing, as in hyperweaver.
Terminal preferences. Font size 6 to 32, scrollback to 200000, cursor style, cursor blink, font family with suggestions, Reset to defaults; saving applies to the open shell at once.
Scrolling. The page region above the row stays the one scroll container; the pane scrolls inside itself; the row rides up as the pane grows. Opening the pane shortens the page region, it never overlays it.
Nothing polls. hyperweaver asked every agent for its tasks every second and the open dialog every two; both go. The pane reads once on open, on the stream's ready and reset, on Refresh and after the person's own action, then follows a tasks topic once the agents stream one. A task's output keeps the WebSocket the agents already push it on, and the shell its own.

Later work. Drawn so its shape is agreed before it is built; this round builds the one Shell of the frames above, and "a tabbed shell per vm" follows in a round of its own.
The strip. One row of tabs at the top of the shell pane, inside the pane, on the shell view alone, drawn only while two or more terminals are open; a single shell draws no strip and is the one Shell of the frames above. The footer's row is the row of every other frame, the grip still the one handle, the Tasks view unchanged.
A tab is a session. Each tab is one terminal with its own session and its own WebSocket, named by its target with its kind beside it; switching shows another terminal and the rest keep running; the × closes the tab and stops its session.
Opened from the Controls menu. No button on the strip opens a terminal: the navbar's Controls menu carries the row, Host actions for the host's shell and Machine controls for the machine's terminal, beside the power rows. What the footer shows by default is what the backend offers, the host terminal; nothing offered and nothing opened, nothing shown.
Footer or page. The row works as the logout row does: its icon is a toggle between the footer's shell, which persists from page to page, and the page's own console area, which ends when the page is left; a click on the icon flips the target and keeps the menu open, a click on the text opens the terminal there. A page without a console area draws no toggle and the row opens in the footer.
Broadcast, later still. One menu that sends the same string at once to every open shell, or to the ones marked to receive it, "just a dumb dump of the string into the shells": the UI writes it into each terminal's own WebSocket, the backend unchanged.
The drop-up and the pane's menu. Reconnect shell, Restart shell and Terminal preferences, as in the one Shell, acting on the tab that shows.

Token Surface
tasks the Tasks toggle, Refresh, the priority filter (All 20, Low+ 40, Medium+ 60, High+ 80, Critical 100, sent as min_priority), the Columns picker, and the tasks pane: one table of the agent's GET /api/tasks rows, fifty at most (ID, Operation, Target, Status, Progress, Priority, Created by, Created, Started, Completed, Error; the Host column first with no host in focus), a row opening the task detail dialog over GET /api/tasks/{id}, /output, the /tasks/{id}/stream WebSocket and DELETE /api/tasks/{id}
host-terminal the Shell toggle and the shell pane, today's terminal source: one xterm over the agent's POST /api/term/start session, its /term/{id} WebSocket opened with an unscoped ticket from GET /api/ws-ticket, fitted to the pane on every drag, the PTY told its size, the session stopped at DELETE /api/term/sessions/{id}/stop when the host changes
