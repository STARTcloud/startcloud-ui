STARTcloud Universal Pages

The picture of the Universal Pages Contract; where the two disagree, the contract's text wins. One page set for every estate app that serves packaged things: an organization owns items, an item has versions, a version has providers, a provider has architectures or artifacts, and a single-file item such as an ISO has one artifact. BoxVault serves boxes and ISOs this way today, the provisioner catalog serves provisioners the same way, and provisioners become a third BoxVault collection later, so nothing on these pages knows which collection it is drawing. The header is the Universal Navbar as it ships; the breadcrumb comes from the route and nothing else; the navbar search and its filter panel are how a page is narrowed, to one collection, one visibility, one provider. The first frame is live: click the brand, a crumb, an organization, a row, a version or a provider and the header and the page follow the route; fold an organization; flip the one list / cards toggle; pick a Collection or Visibility pill in the filter panel; open the user menu and switch organization and only the active organization changes, the page stays where it is.

a yellow note marks what this design changed against the apps as they were before it
Live — the route drives the crumbs and the page; the filter panel narrows it; the switcher drives the active organization and nothing else
What this frame proves. The crumb after the brand is › org › collection › item › version › provider, each level a plain link computed from the route alone; the page draws no breadcrumb of its own; the active organization lives only in the menu row and the switcher.
Changed: the filter panel narrows the page. Any page that lists more than one collection registers a Collection group (Boxes / ISOs) before the shared Visibility group and the collection's own groups; only boxes or only ISOs is a pill, not a page, so the headings are labels with counts and nothing new gets a route.
Changed: home has no Private / Public level. One table per collection with organization group rows; private and public rows sit side by side under the Visibility column, and the Visibility pill narrows to either. The catalog draws the same page, a member's private provisioners inside their organization group with the Private badge.
Changed: the switcher never navigates. Picking an organization sets the active organization for the org console, the ticket id and the create defaults, and leaves the page exactly where it was.
Changed: one toggle per page, headings carry their actions. The list / cards toggle is drawn once per page and holds there; each collection heading row carries the collection's own actions on its right; there are no "All …" links.
Existing BoxVault paths stay: /, /{org}, /{org}/{box}, …/{version}, …/{provider}; /isos, /{org}/isos and /{org}/isos/{iso} are additive, and the Vagrant handler keys on the user agent before any of them.
