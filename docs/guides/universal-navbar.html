STARTcloud Universal Navbar

The picture of the Universal Navbar Contract; where the two disagree, the contract's text wins. The contract covers the right-hand cluster, the search module and its filter panel, the menu, its two modals, the header and footer metrics, and the footer's three slots; brand and layout are each app's own. The header is sticky with a small shadow, a tertiary band with a bottom border, 34px controls with 14px vertical padding and a 20px gutter; the cluster buttons are borderless and abut, the search icon first among them whenever the page has something to search; utility links (About, Docs, Contact) sit in the top bar only while signed out and move into the app-named section once signed in. The first frame is live: every control in it works the way the contract says, on a small BoxVault boxes table, so a reviewer can click through the search, the filters, the theme cycle, the language and organization modals, the notifications, the logout scope and sign-in without running either app. The annotated frames after it carry the explanations. BoxVault and provisioner-catalog are the reference implementations — copy their markup and CSS rather than redrawing from these frames.

    Behaviours — universal rule, and where each lives

    Behaviour Universal rule Today, by file
    Log out everywhere Revoke the app session, then follow the IdP end-session URL (/connect/logout, id_token_hint + post_logout_redirect_uri + state). The IdP may interpose its confirm page (logout-verification, default always) and the front-channel interstitial; back-channel tokens fan out to clients holding an authorization. BoxVault auth.routes.js POST /auth/oidc/logout → redirect_url via buildEndSessionUrl; hyperweaver session.js logout + oidcLogout.js (also revokes the grant); IdP OidcSessionLogoutSuccessHandler, OidcLogoutConfirmationController, OidcBackChannelLogoutService
    Log out of this app Revoke the app session only; SSO survives for seamless re-login; land on the signed-out header. BoxVault AuthService.logoutLocal; hyperweaver logout(true) (local in body); catalog signOut(), with signOutEverywhere() form-POSTing the end-session URL with the kept id_token
    Scope toggle Icon on the logout row flips scope without logging out (stopPropagation); default everywhere; non-OIDC sessions get a plain row. BoxVault renderLogoutIcon (FaBridgeLock/FaHouseLock); hyperweaver SidebarFooter LogoutItem (globe/house, provider label from /api/auth/methods); catalog LogoutItem.jsx (same bridge-lock/house-lock toggle)
    Notices One surface in two tiers: banners in the page flow under the header row for state the user must know before acting, keyed so a repeat replaces, each with icon, text, an optional action and a dismiss; toasts in a fixed column top right, at most four, for feedback on what the user just did, success and info fading after six seconds, warning and danger until dismissed. Field validation, form errors, the error boundary and the callback page stay inline. One hook, notify(kind, text, { tier, key, sticky, action }). Both apps: shared chrome/notices.jsx (NoticeProvider in mountApp, useNotify, NoticeBanners in the Header, NoticeToasts in AppChrome); every page, slot and BoxVault screen raises through useNotify
    Session ended elsewhere Clear local session, render the signed-out header and raise one keyed warning banner under its row with a dismiss and no action of its own; the cluster's Sign in carries returnTo, and dismissing the banner keeps it. BoxVault sessionEvents.js SSE session-terminated and the 401 interceptor → events.endSession() → the banner from AppChrome, the cluster's Sign in → /login?returnTo; hyperweaver AuthContext 401/403 interceptor → Layout guard with hyperweaver_intended_url; catalog refresh failure or 401 → the same banner, one-click sign in
    Back-channel logout Server-side apps register back-channel-logout-uri, verify logout+jwt, correlate by sub/UUID/sid; a public SPA cannot receive it and relies on short access-token TTL + refresh failure. BoxVault backchannelLogout.js (sets sessionsInvalidAfter, pushes SSE); hyperweaver verifyLogoutToken; IdP emits sid only to clients with a logout URI
    Silent SSO Once per session try prompt=none against the default provider; a bounce is benign, never an error. BoxVault login.component.jsx (silent_login + default_provider, sessionStorage flag, ?silent=failed); hyperweaver Login.jsx (?silent → ?sso=unavailable)

    Search — the module's binding

    Field Meaning
    query, onQueryChange the page's query and its setter; the module never keeps a copy
    placeholder the page's own key, e.g. "Search boxes"
    matched, total the live count; hidden when total is 0
    groups[] key, label, entries {value: count}, activeSet, activeClass (or pillClass(value)), optional labelFor(value), onToggle(value)
    onClearFilters empties every set; the × calls it after clearing the query
    searchElsewhere(query) optional, planned: called once the query has two or more characters; answers off-page hits as {app, title, subline, to} for the results list that drops under the panel — grouped by app then collection under an "Elsewhere in <app>" heading, each row an icon, a title, org · collection · version and the deep link of the universal route shape; click or Enter navigates, arrows move, Escape returns to this-app mode with the query kept.     Lifetime registered by useNavbarSearchBinding for as long as the page component is mounted; one binding at a time, the last page to register wins; a page with two independent lists would need named bindings, which the module does not have
