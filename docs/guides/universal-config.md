## Universal Config Contract

{: .no_toc }

One configuration engine on every backend: plain YAML files an administrator
reads and edits, and beside the code one JSON Schema document per file that
says what every value is, what it is allowed to be, how it is drawn and what
happens when it changes. The schema is the [Universal Validation
Contract](universal-validation/)'s rule set applied to configuration, so the
setup page, the admin page and the write route evaluate one document and
refuse a bad value the same way with the same body. This contract is the one
specification of that engine: the boot sequence, the file layout, the schema
document, the routes and their answers to the member and the status code,
the absence of secrets handling, restart reporting, actions, maps, the
drop-in module per language, the per-backend records and the conformance
checklist. Every clause is a rule with one reading, carries its reason, and
cites the specification or practice it follows where one exists, so a
deviation is an argument with the citation, never with the author. It
extends the [Universal Navbar Contract](universal-navbar/), whose status
payload names the files. The visual reference is
[universal-config.html](../universal-config.html).

## Principles

- **The file is plain.** A leaf holds its value and nothing else:
  `api_listen_port_encrypted: 443`. Configuration is YAML files and no other
  format: no JSON, no properties, no TOML, no database row, and no metadata
  node around a value. Why: what every Unix service does; readable in a
  pager, diffable across releases, editable by hand.
- **The file is the source of truth.** A read returns what the file holds; a
  write changes only what was sent; a default lives in memory and in the
  editor's placeholder and never in the file; a read never rewrites the
  file. Why: a second place a value lives is a second place it differs.
- **The files live under `CONFIG_DIR`, default `/etc/<app>`.** One
  directory per service on Linux, where an administrator looks first (FHS
  3.0 §3.7). The authorization server's default is
  `/opt/prominic/authorization-server/config`, the one named exception,
  because its package already installs there and moving it breaks every
  existing install for no gain.
- **The unit owns the configuration directory.** Every service runs as its
  own system user, never root; the systemd unit carves the directory out for
  that user with the three lines `ConfigurationDirectory=<app>`,
  `ConfigurationDirectoryMode=0750` and `ReadWritePaths=/etc/<app>` under
  `User=<app>`, one shape for every backend under `/etc` (systemd.exec(5)
  `ConfigurationDirectory=`, `ConfigurationDirectoryMode=`,
  `ReadWritePaths=`). The package ships `/etc/<app>/` in its payload;
  `postinst` sets its owner to the service user and its mode to `0750`,
  copies each seed configuration file and the empty setup token file only
  where no file of that name exists, and never overwrites on an upgrade
  (Debian Policy §10.7); the unit's `ConfigurationDirectory=` and
  `ConfigurationDirectoryMode=0750` re-assert the owner and mode on every
  start and create nothing the package did not ship (systemd.exec(5));
  neither step depends on the other's order. The authorization server's
  `/opt/prominic/authorization-server/config` keeps `ReadWritePaths=` alone
  as its named exception. Why: `ConfigurationDirectory=` by itself neither
  adds the directory to `ReadWritePaths=` nor sets `0750`, so under
  `ProtectSystem=strict` the write path is stranded on every backend; the
  three lines together are what grants the directory on every boot, and a
  `chown -R` in a script is a grant that lasts until the next hand edit.
- **The schema is the backend's, versioned with its code.** Rules and drawing
  words live in one JSON Schema 2020-12 file per YAML file, shipped in the
  package, never in `CONFIG_DIR`. Why: an administrator cannot edit or break
  a rule and an upgrade brings the new rules with it.
- **One evaluator.** The schema is JSON Schema 2020-12 keywords plus this
  contract's drawing words; the shared UI's validator and every backend's
  route evaluate it the way the validation contract's forms are evaluated.
- **Validate, then write.** A `PUT` is refused with 422 and pointers before
  anything touches the file; a file that fails its schema at boot stops the
  backend with every failing pointer logged.
- **There is no secrets handling.** No environment variable carries a value,
  no secret file sits beside the YAML, nothing is encrypted, hashed or masked
  on the way in or out. Why: the directory's ownership and mode are the
  protection every other file under `/etc/<app>` has; a second mechanism is
  a second place a value differs from the file.
- **A restart is named, not guessed.** Whenever a write leaves a restart
  pending the answer lists the settings that need it and why, and the list
  is readable back until the restart happens.
- **An action is a schema word, not page code.** An upload, a test and a
  run are declared on the property or section they belong to, and the UI
  draws one component per kind. Why: a backend with a seventh action needs
  no UI release.
- **One module per language, copied verbatim.** The engine is one drop-in
  file per language with one seam; a backend supplies its names list, its
  code rules and its exit function and nothing else. Why: a versioned
  library is a second release train the estate does not run.
- **One environment variable, no more.** `CONFIG_DIR`. Everything else, the
  production-versus-development switch included, is a value in a file;
  which config directory exists chooses the environment. A backend with no
  files (the provisioner catalog) reads its platform's `env` and is outside
  this rule, because it has no file for a value to live in.

### A file and its schema

`/etc/boxvault/app.config.yaml`:

```yaml
schemaVersion: 1
boxvault:
  origin: https://boxvault.startcloud.com
  api_listen_port_unencrypted: 80
  api_listen_port_encrypted: 443
  box_storage_directory: /var/lib/boxvault/storage
  trust_proxy: true
gravatar:
  api_key: 3f9c…
logging:
  level: info
  categories:
    app: info
    api: info
```

`backend/app/config/schema/app.schema.yaml`:

```yaml
$schema: https://json-schema.org/draft/2020-12/schema
title: Application
schemaVersion: 1
sections:
  application:
    title: Application
    order: 1
properties:
  schemaVersion:
    type: integer
    readOnly: true
    default: 1
    title: Schema version
  boxvault:
    type: object
    section: application
    subsection: boxvaultSettings
    title: BoxVault Settings
    properties:
      origin:
        type: string
        format: uri
        title: Origin
        description: The origin URL for BoxVault
        order: 1
        requiresRestart: true
        restartReason: the listener and the OIDC redirect are bound at boot
      api_listen_port_encrypted:
        type: integer
        minimum: 1
        maximum: 65535
        default: 443
        title: HTTPS port
        description: The port BoxVault listens on for HTTPS; the proxied port is a separate value
        order: 4
        requiresRestart: true
        restartReason: the listener is bound at boot
    required: [origin, api_listen_port_unencrypted, api_listen_port_encrypted]
  gravatar:
    type: object
    section: application
    subsection: gravatarSettings
    properties:
      api_key:
        type: string
        writeOnly: true
        title: Gravatar API key
        order: 2
  logging:
    type: object
    section: application
    subsection: loggingSettings
    properties:
      level:
        type: string
        enum: [error, warn, info, debug]
        default: info
        title: Log level
        order: 1
      categories:
        type: object
        subsection: loggingCategories
        additionalProperties:
          type: string
          enum: [error, warn, info, debug]
```

## The schema document

One JSON Schema 2020-12 document per file. The rules are the validation
contract's vocabulary; the drawing words are this contract's additions, which
the spec admits as annotations (Core §7.7.1).

## 3. Routes and answers

Every route is admin-only unless the row says otherwise; every refusal is the
validation contract's problem body, `application/problem+json`, with `type`
under `https://auth.startcloud.com/probs/` (RFC 9457 §3); every body member
is `snake_case`; `<name>` outside `status.config` is 404 `not-found` on every
row (RFC 9110 §15.5.5); a caller who is not an admin is 403 `forbidden`
(§15.5.4); an unreadable body is 400 `bad-request` (§15.5.1).

| Route                            | Answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Why                                                                                        | Spec                                   |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------- |
| `GET /api/config/<name>`         | 200, the raw file parsed to JSON and nothing else: no default filled, no value masked, no key added, no key removed; a YAML null leaf (`api_key:`) is answered as JSON `null`, which the editor draws as an empty control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | the editor edits the file, not the process's view of it                                    | this contract; YAML 1.2 §10.2.1.1 null |
| `GET /api/config/<name>/schema`  | 200, the schema document verbatim as JSON                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | the schema carries no value, so any admin reads it                                         | this contract                          |
| `PUT /api/config/<name>`         | the body is a JSON Merge Patch over the raw file (RFC 7396): a sent key replaces the stored value, an omitted key is untouched, `null` removes the key, a sent blank (the empty string `""`) is written as the empty string, an array replaces the stored array whole, an object recurses; the editor's `patchOf(before, after)` sends four cleared-control cases and no other: a cleared text control sends `""`, a cleared numeric control sends `null` because there is no blank number, a map Delete sends `null` for the key, and a switch sends `true` or `false`; the route fills `default` into the merged result in memory, evaluates it against the schema and the backend's two hooks `writable` and `reachable`, and answers 422 `validation` with one `errors[]` entry per failing value whose `pointer` is into the body as sent; when none fails it writes the unfilled merge atomically with the `.bak` and answers 200 `{ "message": "Configuration saved.", "requires_restart": [ { "pointer": "/boxvault/api_listen_port_encrypted", "title": "HTTPS port", "reason": "the listener is bound at boot" } ] }`, the list being section 5's diff, `[]` when no flagged leaf changed | one merge semantics on every backend; a blank is a value; a default never reaches the file | RFC 7396 §2                            |

The refused write is the validation contract's body:

```json
{
  "type": "https://auth.startcloud.com/probs/validation",
  "title": "The configuration did not pass validation.",
  "status": 422,
  "errors": [
    {
      "pointer": "/boxvault/api_listen_port_encrypted",
      "rule": "maximum",
      "params": { "maximum": 65535 },
      "detail": "api_listen_port_encrypted must be at most 65535"
    },
    {
      "pointer": "/logging/log_directory",
      "rule": "writable",
      "params": { "user": "boxvault" },
      "detail": "/var/log/boxvault is not writable by boxvault"
    }
  ]
}
```

A rule the schema cannot express is code on the route, supplied to the
module as the `writable` and `reachable` hooks, and answers in the same entry
with that named rule; the UI paints it from `validation.<rule>` with the
field's `title`. `writable` carries `params: { "user": "<service user>" }`
and `reachable` carries `params: { "host": "<host>", "port": <port> }`, so
the sentence names what the administrator has to change; both hooks compare
the property's value resolved to an absolute path against the resolved
absolute `CONFIG_DIR`, never string against string. `reachable` is a TCP
connect to the host and port with a timeout of 3 seconds, never a DNS lookup
alone, because a resolvable host with a closed port is the failure the rule
exists to report. `writable` runs at `load` and at `save`; `reachable` runs
at `save` alone, because a mail host or a database peer that is down at boot
must never keep a service from starting, and the person saving is the one
who can act on the answer. `range` is not a rule of
this contract: a value outside both bounds reports `minimum` or `maximum`,
whichever it crossed.

The setup token follows the first-boot pattern of Jenkins (the initial admin
password written to a file under the service's home) and Grafana (the
first-boot admin credential replaced on first use): `postinst` creates an
empty `setup.token` (mode `0600`, owned by the service user) on first
install, in the same run that copies the packaged templates, and never on an
upgrade; at `load` the backend fills an empty `setup.token` with 32 random
bytes written as 64 hex characters and logs its path, leaves a non-empty one
as it is, and the `PUT /api/setup` that succeeds deletes it; setup is
complete exactly when the file does not exist.

## 6. Actions

An action is a schema word on a property or on a section
(`sections.<key>.action`):

```yaml
action:
  kind: upload
  route: /api/config/app/upload
  method: POST
  body: file
  step_up: false
```

| Member    | Value                                    | Meaning                                                                                                                                                                                                                                                                                                                                                               |
| --------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kind`    | `upload`, `test`, `run`                  | which component the UI draws                                                                                                                                                                                                                                                                                                                                          |
| `route`   | an absolute path on the backend's origin | what the component calls                                                                                                                                                                                                                                                                                                                                              |
| `method`  | `POST`                                   | the one method an action uses                                                                                                                                                                                                                                                                                                                                         |
| `body`    | `file`, `form`, `none`                   | `file`: multipart with the parts `file` and `pointer`, the upload route of section 3; `form`: the current form values as JSON, unsaved, so a test exercises what the administrator is about to save: for a property action the object that holds the property, for a section action an object of the section's top-level properties under their keys; `none`: no body |
| `step_up` | `true`, `false`                          | `true`: the route answers `403 step_up_required` outside the step-up window, and the UI opens the step-up dialog and retries the same call unchanged, the one flow every sensitive call follows (identity contract decision 38); nothing is armed in advance; `false`: the route never asks                                                                           |

| Rule                   | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Why                                                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |

## Upgrades and migrations

| Case                   | What happens                                                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| a new key              | its `default` is filled in memory at `load`; the file gains the key only when an administrator writes it                                                                                                                                                    |
| a removed key          | logged as unknown at boot; the release's migration drops it from the file in `postinst`                                                                                                                                                                     |
| a renamed or moved key | one entry in the backend's migration list, a function per release, run by `postinst` in order against the file's `schemaVersion`; the migration reads the old key, writes the new key, drops the old key and stamps `schemaVersion`; it writes nothing else |
| a changed rule         | the tightened rule applies at boot; a value that no longer passes stops the backend with its pointer                                                                                                                                                        |
| a changed default      | only a missing key takes it, in memory; a value the administrator set is never overwritten                                                                                                                                                                  |
| a missing file         | `postinst` copies `packaging/config/<name>.config.yaml`; no migration runs on a file that did not exist                                                                                                                                                     |

The file carries `schemaVersion: <n>` at its root; the schema carries the
same; `postinst` runs the migrations from the file's version to the schema's
and writes the new version, as the service user (`runuser -u <user>`), with
the `.bak` of section 2. A migration never materializes a default and never
re-serializes a key it did not change beyond what a YAML dump of the parsed
document does. The dev files in the tree are migrated by hand and committed.
Which mechanism carries a migration to an existing install is each
backend's own and is recorded in section 9.

## Decisions

Settled before code, in the order they were raised:

1. `CONFIG_DIR` is the one environment variable on every backend; its
   default is `/etc/<app>` and `/opt/prominic/authorization-server/config`
   on the authorization server, which keeps `SPRING_PROFILES_ACTIVE` as its
   recorded second variable and nothing else.
2. The environment is chosen by whether `CONFIG_DIR` exists; `VDI_HEALTH_ENV`
   goes.
3. `default` is filled in memory at `load` and drawn as the editor's
   placeholder; no route, migration or boot step writes it into the file.
4. A read never rewrites the file; the module's cache is replaced on `save`
   and never otherwise; a hand edit takes effect at the next restart.
5. `GET /api/config/<name>` answers the raw file and nothing else.
6. `PUT /api/config/<name>` is a JSON Merge Patch (RFC 7396): `null`
   removes, a blank is written blank, an omitted key is untouched, an array
   replaces whole; the unfilled merge is what is written; the authorization
   server's placeholders are the one exception, decision 87.
7. The write is a temp file in the same directory renamed over the target,
   mode `0600`, with one `<name>.config.yaml.bak` beside it; timestamped
   backups go.
8. There is no secrets handling: no mask, no keep-on-blank, no sentinel, no
   presence flag, no `${ENV}` placeholder, no `.env` loader; the shared
   evaluator's `SECRET_MASK` and `keepsSecret` go.
9. `writeOnly` is the reveal hint of the GOV.UK password input and nothing
   more.
10. `requiresRestart: true` is paired with `restartReason` on every flagged
    leaf; the 200 lists the changed flagged leaves as
    `{ pointer, title, reason }`; the pending union is answered by
    `GET /api/config/restart-status` until `POST /api/config/restart`.
11. `POST /api/config/restart` answers 202 and calls the backend's exit
    function; the authorization server exits the JVM in place of its
    in-process context rebuild, and its dead `management.endpoint.restart`
    knobs go.
12. A boot-bound backend flags every leaf with the one reason
    `configuration is bound at boot`.
13. `action: { kind, route, method, body, step_up }` is the one action word;
    `upload: true` is retired for `action.kind: upload`; one upload route
    `POST /api/config/<name>/upload` with the parts `file` and `pointer`
    serves the admin page and the setup page.
14. The SMTP test is a `test` action on the mail section with `body: form`,
    sent to the caller's own address.
15. The admin adapter is `get`, `schema`, `update`, `restartStatus`,
    `restart` and one `action(route, method, body)`.
16. Every `additionalProperties` field is drawn by one generic map component
    keyed by its item schema; the providers block stops being a named
    pointer in page code; sites, clients, providers and SMTP hosts are such
    maps; the key rule is `propertyNames`; a card shows the key and every
    item property carrying `order` 1 or 2.
17. The engine is one drop-in file per language with the nine-entry seam
    of section 8, `get` counted in both arities; the first backend per
    language holds the source; copies are verbatim; there is no versioned
    library.
18. The backend supplies the names list, the `writable` and `reachable`
    hooks, the exit function, the `auth` guards and `uploadLimit`; the
    module does the rest.
19. The tab label is the schema's root `title`; `configManager.tabs.<name>`
    goes.
20. `status.config` is exactly the names list; `[]` on a backend with no
    files; a missing member is read as `[]`; the editor draws an empty
    state and no tab for `[]`.
21. Every refusal on every config and setup route is a problem body; the
    `{ "message" }` 404s go.
22. `GET /api/setup/status` answers `{ "setup_complete" }`;
    `POST /api/setup/verify-token` answers 204, 403 or 404 after
    completion and hands nothing back; the setup token follows the Jenkins
    and Grafana first-boot pattern.
23. The setup routes are the module's and exist on every backend with
    files; the VDI Health Monitor and the authorization server gain them
    with the module.
24. `postinst` copies `packaging/config/<name>.config.yaml` from its
    packaged location for a missing file, never over a file that exists,
    and runs the migration list as the service user; a migration writes
    only the keys it changes and `schemaVersion`.
25. The unit grants the directory with `ConfigurationDirectory=<app>`,
    `ConfigurationDirectoryMode=0750` and `ReadWritePaths=/etc/<app>`
    under `User=<app>`, one shape for every backend under `/etc`, and
    re-asserts the owner and mode on every start; `chown -R` in `postinst`
    goes; the authorization server's `/opt` directory keeps
    `ReadWritePaths=` alone.
26. The dev files are `<module dir>/../../config/<name>.dev.config.yaml`,
    the directory resolved from the module's own file location and never
    from the working directory, committed and migrated by hand;
    BoxVault's move out of `backend/app/config/` and the VDI Health
    Monitor's leave `.gitignore`.
27. `schemaVersion` is a `readOnly` integer property of every schema with a
    `default` equal to the root value, and the one camelCase key in a file.
28. The authorization server's phase one is one file named `application`
    under `CONFIG_DIR`, `status.config: ["application"]`, the Groovy module
    beside Spring for read and write, Spring loading the same file through
    `--spring.config.additional-location` on `ExecStart`; the split into
    named files is a later phase.
29. The authorization server's key case is its recorded exception: Spring's
    namespaces, JavaMail's property names and the kebab-case maps stay; the
    editor is case-blind; `idFor` answers the full pointer verbatim.
30. `security.provider_secrets.key` stays as a plain value in the file
    protecting database rows; the rows are not configuration.
31. The catalog answers `config: []` and has no config routes; its
    name-less `GET /api/config` is its recorded public subset; every line
    of the checklist reads `n/a` for it; a backend with no files reads its
    platform's `env` and is outside the one-variable rule.
32. `range` is not a rule; a crossed bound reports `minimum` or `maximum`.
33. `format` is a rule and never a control.
34. `required` is presence alone on every backend; a blank string fails
    `minLength: 1` and `pattern: "\\S"`, never a trim; a blank string is
    evaluated against `minLength`, `pattern` and `required` alone and
    skips `format`, `enum`, `minimum` and `maximum`.
35. Every array carries `items`; scalar `items` draw as a comma list
    evaluated per member, `items.enum` as a multi-select, and `items` of
    `type: object` is not a shape of this contract; a free subtree is
    neither drawn nor evaluated nor walked; a per-pool or per-site subtree
    the editor is to draw gains an item schema.
36. The engine's `load` runs before every other read of configuration in
    the process.
37. The Restart button is behind a confirm dialog on every backend; on a
    `cookie` backend the route answers `403 step_up_required` outside the
    step-up window and the UI opens the step-up dialog and retries, as
    identity contract decisions 29 and 38 say; nothing is armed in
    advance.
38. The public subsets are each backend's own and are listed in section 9,
    not fixed by this contract; `GET /api/config/grafana` is the VDI Health
    Monitor's, not BoxVault's; a subset answers the values as the backend
    holds them.
39. The visual reference `universal-config.html` is brought to this text in
    the shared UI's round; the shared UI carries a test fixture of the
    config and setup routes under the testing contract's runner, never a
    dev proxy target, and its tests for `schemaSections`, `validation`,
    `useFormRules`, `AdminConfig` and `SetupPage` land with that contract.
40. Development is section 2 with `<module dir>/../../config` for
    `<CONFIG_DIR>` and `.dev.config.yaml` for `.config.yaml`, the directory
    resolved from the module's own file, and differs in nothing else.
41. `load` fills `default` recursively through `properties`, creating in
    memory an object the file lacks when a descendant carries a `default`,
    and never descends into an `additionalProperties` entry; the refuse
    lines go through the `app` category at the logger's built-in level and
    destination.
42. An upload is written at the path the property holds; the 413 bound is
    the `uploadLimit` the backend passes to `routes`; a `pointer` naming no
    upload property is 422 rule `pointer` at `/pointer`.
43. A `PUT` carrying a `readOnly` pointer is 422 rule `readOnly` at that
    pointer; `readOnly` is `schemaVersion` alone, because a value the code
    derives is computed from the stored key and never stored.
44. `sections` is a map of key to `{ title, order, action }`; subsections
    order by their object property's `order`; unordered fields follow
    ordered ones in key order; a top-level property in no section draws in
    `general`, titled `General`, last.
45. `dependsOn` is a sibling key, `showWhen` an array of its values; both
    sides evaluate the field only while the sibling's value is equal by
    JSON value to a member; a hidden field's stored value stays.
46. The `message` sentences are `Configuration saved.`, `Restarting.` and
    `Setup complete.`.
47. Setup is complete exactly when `setup.token` is absent; `postinst`
    creates it empty on first install; `load` fills an empty one with 64
    hex characters; every setup route but `status` is 404 after
    completion and 403 on a missing or mismatched token; `PUT /api/setup`
    writes through `save` with actor `setup` and answers `{ "message" }`
    alone.
48. `load` stops the process on a flagged leaf without `restartReason`.
49. `body: form` on a section action is the section's top-level properties
    under their keys; `test` answers 200, `run` 202, `upload` 200
    `{ "path" }`; a `test` or `run` button sits at the section head when
    declared on a section and beside the control when on a property.
50. Map Add, Delete and Remove change the form alone and travel in the next
    Update's merge patch.
51. The seam is `load(configDir, names, schemaDir, hooks)` and
    `routes(app, auth, exit, uploadLimit)`, `hooks` carrying `writable`,
    `reachable` and `onSaved` when the backend supplies one, `auth.stepUp`
    present on a `cookie` backend alone.
52. `last_modified_time` is UTC with the `Z` suffix; a blank is the empty
    string `""`.
53. `deprecated` draws the note `configManager.deprecated`; a property
    without `title` is labelled by its key.
54. No backend watches the config directory.
55. A generated key is BoxVault's VAPID pair or the VDI Health Monitor's
    JWT secret, written through `save`.
56. The unit owns the directory: `ConfigurationDirectory=<app>`,
    `ConfigurationDirectoryMode=0750` and `ReadWritePaths=/etc/<app>` under
    `User=<app>` on every backend under `/etc`, re-asserting the owner and
    mode on every start and creating nothing the package did not ship; the
    package ships `/etc/<app>/` in its payload; the authorization server's
    `/opt` directory keeps `ReadWritePaths=` alone.
57. `postinst` sets the shipped directory's owner to the service user and
    its mode to `0750`, copies the seed files from the packaged location of
    `packaging/config/<name>.config.yaml` and the empty `setup.token` only
    where no file of that name exists, and never overwrites on an upgrade
    (Debian Policy §10.7); neither `postinst` nor the unit depends on the
    other's order.
58. The development directory is resolved from the module's own file
    location, never from the process working directory; `writable` and
    `reachable` compare resolved absolute paths.
59. `propertyNames` is a keyword of the validation contract's vocabulary
    (Core §10.3.2.4), the rule a map's key meets, evaluated in the browser
    with `unique` on the map's existing keys.
60. `onSaved(name, actor)` is the ninth seam entry, the backend's own,
    called by `save` after the write and the cache replace, once per file
    written on `PUT /api/setup`, absent on a backend that needs nothing.
61. A value the code derives is computed from the stored key and never
    stored in the file; BoxVault's `sql.dialect` goes; `readOnly` is
    `schemaVersion` alone.
62. A cleared text control sends `""`, a cleared numeric control sends
    `null`, a map Delete sends `null`, a switch sends `true` or `false`;
    `GET` answers a YAML null leaf as JSON `null`.
63. The `message` member of a 200 or 202 is for `curl` and the log; the UI
    draws its own success card from `configManager.updateSuccess`,
    `configManager.actions.testPassed`, `configManager.actions.runStarted`
    and `configManager.restarting`, never the server's sentence.
64. A `run` action's confirm dialog takes its title from the property's or
    the section's `title` and its body from
    `configManager.actions.runConfirm` with `{{title}}`; no schema member
    carries a sentence.
65. `step_up: true` means the route answers `403 step_up_required` outside
    the window and the UI opens the step-up dialog and retries, the
    identity contract's one flow; no pre-arm.
66. `default` is the `placeholder` of a text or numeric control and the
    `configManager.defaultHint` line of a boolean or an `enum`, whose
    control stays unset until the administrator sets it.
67. Scalar `items` draw as a comma list evaluated per member; `items.enum`
    draws as a multi-select; `items` of `type: object` is not a shape of
    this contract.
68. The editor never draws the `PUT`'s list directly; the card is one
    shared `RestartCard` fed by `restart-status` on the config page and the
    issuer's dashboard; the `restart-required` event triggers a re-read and
    carries `{ required, last_modified_by, last_modified_time }` alone.
69. A map card shows the key and every item property carrying `order` 1 or
    2; the dialog shows the rest.
70. `idFor` answers `${idPrefix}${pointer}` verbatim for every form;
    `Field.jsx` and `FormErrorSummary.jsx` follow; a kebab-case property on
    the authorization server carries a `title` because the sentence names
    the `title`, never the key.
71. A schema's `title` and `description` are English text drawn as they
    are, the one carve-out from the translation rule, because the schema is
    code shipped with the backend.
72. On a backend whose `status.config` is `[]` the admin adapter carries no
    `config` member, the sidebar draws no Configuration row, and the empty
    state is reached by URL alone.
73. When `setup_complete` is `true` the setup page draws `setup.complete`
    with one link, to `/login` on a backend with accounts and to `/`
    otherwise, and neither the token card nor the tabs; a 403 on the token
    paints `setup.tokenInvalid` on the token field.
74. `writable` carries `params: { user }` and `reachable` carries
    `params: { host, port }`.
75. `showWhen` equality is equality by JSON value.
76. A blank string is evaluated against `minLength`, `pattern` and
    `required` alone.
77. `load` never fills an `additionalProperties` entry; a map item's
    `default` is the editor's placeholder alone.
78. A custom tag is refused at `load` with its pointer; an anchor or a merge
    key in a hand-edited file is seen only through its resolved values, with
    no pointer to the anchor.
79. The exit function ships on a platform only after that platform's
    process manager restarts the process; BoxVault's SMF manifest with
    `startd/duration = child` precedes it on OmniOS.
80. A backend with no files reads its platform's `env` and is outside the
    one-variable rule; its public subset answers the values as it holds
    them.
81. The development directory is `<module dir>/../../config`, resolved from
    the module's own file; on a Node backend with the module at
    `backend/app/utils/` it is `backend/config/`.
82. `reachable` is a TCP connect to the host and port with a 3 second
    timeout, never a DNS lookup alone; a resolvable host with a closed
    port is the failure the rule exists to report.
83. `last_modified_by` is the acting person's email address as a string;
    `actor` in `save(name, body, actor)` is that same string.
84. The host calls the nine seam entries and nothing else; a module keeps
    another export only while no host code imports it.
85. On OmniOS `setup.token` ships in the IPS manifest with
    `preserve=abandon` (pkg(7) `preserve`), installed only when absent and
    never re-delivered on upgrade once deleted; Debian gets the same effect
    from `postinst` copying only where absent.
86. `writable` runs at `load` and at `save`; `reachable` runs at `save`
    alone, because a mail host or a database peer that is down at boot
    must never keep a service from starting, and the person saving is the
    one who can act on the answer.
87. The authorization server alone may write `${NAME:default}` placeholders
    in `application.config.yaml`; every other backend stays on decision 6
    with no placeholders. The engine resolves a placeholder from the
    process environment at `load`; the default applies when the name is
    unset; a placeholder with neither a value nor a default is a validation
    failure with rule `placeholder`, `params: { "name": "<NAME>" }`, at the
    leaf's pointer. `GET` answers the raw file with every placeholder leaf as
    `{ "value": "${NAME:default}", "resolved": true }`, the placeholder text
    intact, so the editor can show the live value on reveal. On `PUT` a leaf that held a
    placeholder keeps it when the merge patch omits it; a patch that sets
    the leaf writes the literal and detaches it from the environment. The
    packaged unit keeps `EnvironmentFile=/etc/auth-server/env`, readable by
    the service user only. At cutover only values with no placeholder in
    the file move by hand.
